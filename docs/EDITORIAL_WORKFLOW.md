# Visual Art Atlas 日常收录流程

本流程用于逐篇人工新增档案。选题由研究价值决定，缺图可以登记后继续；正式发布前必须核验内容来源、数据结构和页面呈现。当前没有自动选题、付费 AI API 或定时发布步骤。

## 单篇制作顺序

1. **确定问题与范围**：一句话说明这篇要帮助读者看懂什么，再决定 `topicType`、七大分类之一、时期、地区和适量的代表作品或研究实例（通常 2–4 个）。题材不以找图结果为前提。
2. **先找可靠文字来源**：优先使用馆藏、档案、艺术家/机构原始资料和学术出版物。每项正式来源记录标题、URL、发布者、核验日期与核验说明。无法支持关键事实时先保留为草稿。
3. **独立核验图像**：对每幅图片核对对象身份、版本、作者、许可范围、署名和本站展示用途；逐项记录在 `docs/evidence/`。图片未解决时保留作品的 `sourceUrl`，把缺图原因放入选题表和来源记录，不用猜测性授权信息。
4. **写档案 JSON**：在 `src/data/entries/` 新建 `<YYYY-MM-DD>-<slug>.json`。复制既有条目结构，稳定 ID 与日期对应。`status` 初始设为 `draft`；正式来源与作品来源必须是真实 HTTPS 页面。缺图时 `works[].image` 或 `cover` 可为 `null`。
5. **编写视觉速记**：`style_summary` 以完整档案标题开头，接 ASCII 连字符 `-`，再接 4–7 个中文逗号分隔的短视觉描述。例如：`罗丹：身体如何承载情绪-粗粝可见的塑形痕迹，厚重体块与扭转姿态，明暗沿肌理起伏，青铜表面承接身体张力`。标题负责标出主题，后半段提炼媒介、构图、色彩、光影、笔触、造型、材料或气质；总长建议 30–65 字。避免生平、艺术史和空泛评价。
6. **检查标签与同义词**：使用 `src/constants/taxonomy.ts` 中的固定分类、主题类型和视觉特征 key。`regions` 只放地区，`period` 放时期，`tags` 放可复用视觉概念、材料、媒介和方法；优先沿用已有中文标签。需要稳定支持的中英文词或常见写法，作为一组加入 `synonyms`，不要只为单篇标题扩充映射。
7. **校验并本地预览**：将候选 JSON 保存在仓库外，依次运行：

   ```bash
   npm run import:entry -- /absolute/path/candidate.json --dry-run
   npm run import:entry -- /absolute/path/candidate.json
   npm run validate:content
   npm run check
   npm test
   npm run build
   npm run preview
   ```

   `dry-run` 只验证候选，不写入仓库。确认通过后才运行正式导入。预览桌面与手机页面，逐项检查标题、来源、图片身份、署名、缺图行、速记复制、关联档案和搜索标签。

8. **人工发布**：逐条完成内容事实与图片许可审阅后，将该条目的 `status` 改为 `published`，提交 PR 并检查质量工作流；合并到 `main` 后由 Pages 工作流部署。草稿不应包含不能公开的敏感信息，因为公开仓库可见其 JSON。

## JSON 字段骨架

以下仅说明字段组织，不是可直接导入的 JSON。逐篇复制现有档案结构，再以真实核验后的内容替换示意字段；不能把示意来源、标题或许可提交为档案数据。

```json
{
  "schemaVersion": 1,
  "id": "YYYY-MM-DD-topic-slug",
  "date": "YYYY-MM-DD",
  "status": "draft",
  "title": "档案主题标题",
  "subtitle": "主题说明",
  "topicType": "technique",
  "category": "digital_art",
  "period": null,
  "regions": [],
  "tags": [],
  "summary": "一句话说明这篇档案帮助读者看懂什么。",
  "style_summary": "档案主题标题-媒介技法，构图关系，色彩与光影，材料质感",
  "visualFeatures": [],
  "context": "已核验的背景与语境。",
  "people": [],
  "works": [],
  "comparison": null,
  "applications": [],
  "experiment": null,
  "nextTopics": [],
  "relatedIds": [],
  "cover": null,
  "sources": [],
  "updatedAt": null
}
```

## 数据约定速查

- 日期和 ID：`YYYY-MM-DD` 与 `YYYY-MM-DD-slug` 一致；已发布 ID 不复用。
- 内容类型：`movement`（艺术流派）、`artist`（创作者）、`artwork`（作品档案）、`technique`（技法与材料）、`design_method`（设计方法）、`cross_disciplinary`（跨界主题）。
- 视觉分析：选择实际适用的 3–6 个 `visualFeatures`，不要为了凑齐字段覆盖无关维度。
- 搜索标签：中文为主、精简且可跨条目复用；英文别名维护在 `synonyms`，而不是重复塞入每条 `tags`。
- `style_summary`：标题 + `-` + 4–7 个短描述；字段是可选的，旧档案缺失时详情页隐藏模块。新增正式条目应补齐，以便复制和检索。
- 图片：保留原图身份、许可与署名证据。真实作品图片、纪实图片、原创封面和技法示意要明确区分。
- 草稿导入仅接收新 ID 的 `draft`，不会覆盖旧记录、调用 API、提交 Git 或发布。
